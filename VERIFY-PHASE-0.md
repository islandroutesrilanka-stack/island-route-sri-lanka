#### 1a. The URL bug, concretely

`layout.tsx` read `NEXT_PUBLIC_SITE_URL` for canonicals. `sitemap.ts` hardcoded `site.url`. Set that env var to anything else — a staging host, a Vercel preview — and your canonicals point at one origin while your sitemap points at another. Hard to notice, unpleasant to unwind. Now there is exactly one source of truth.

## 3. SQL to run manually

### Required — one migration

**`supabase/migrations/0001_updated_at.sql`** → paste into Supabase SQL Editor → Run.

- Additive and idempotent. Safe to run repeatedly, safe against live data.
- Nothing is dropped; no existing column is altered.
- Adds `updated_at` + an auto-update trigger to all 8 content tables, backfills from `created_at` where it exists, adds supporting indexes.
- Guarded with `to_regclass` so it is safe even on a fresh project where `schema.sql` hasn't run yet.

Verify it worked:

```sql
select table_name
from information_schema.columns
where table_schema = 'public' and column_name = 'updated_at'
order by table_name;
```

Expect 9 rows: `destinations`, `drivers`, `gallery`, `posts`, `reviews`, `services`, `site_settings`, `tours`, `vehicles`.
